# 8. Troubleshooting - Kiwi Server

This chapter is intended to help with known problems, pitfalls and issues.

If you don't find the solution to your problem here, please amend this document once the issue is solved to document
how to resolve it.

## NullPointerException in EntitySchema object initializer

You may encounter an error during startup indicating that a `NullPointerException` was thrown while initializing an
`EntitySchema` object. The root cause of the stacktrace may look similar to this:

```
Caused by: java.lang.ExceptionInInitializerError: null
	[...]
Caused by: java.lang.NullPointerException: parentList must not be null
	at com.example.domain.schema.TodoItemSchema.<clinit>(TodoSchema.kt:21) ~[main/:na]
```

This problem occurs when the entity classes declared are not included in the JPA persistence unit generated by the
Spring Framework. Consequently, the static JPA Metamodel fields will not be initialized.

Example metamodel class generated by Hibernate JPA-Modelgen:

```java

@StaticMetamodel(TodoItem.class)
@Generated("org.hibernate.processor.HibernateProcessor")
public abstract class TodoItem_ extends de.kiwi.api.domain.BaseEntity_ {

    public static final String TODO_LIST = "todoList";
    public static final String CONTENT = "content";
    public static final String COMPLETED = "completed";

    // (!) These static volatile meta-attributes have not been initialized, so they are `null`
    public static volatile EntityType<TodoItem> class_;
    public static volatile SingularAttribute<TodoItem, TodoList> todoList;
    public static volatile SingularAttribute<TodoItem, String> content;
    public static volatile SingularAttribute<TodoItem, Boolean> completed;
}
```

To resolve this, make sure that:

1. The JPA persistent unit has been initialized
2. An `@EntityScan` annotation is present on an active configuration class, and scans the package where your entity
   classes are defined
